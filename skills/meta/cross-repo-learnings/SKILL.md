# Cross-Repo Learnings

リポジトリを越えて効く知見を、まとめのファイルに外部化する。この skill が持つのはまとめの書式と書き方まで。まとめを集約先へ届けるのは対になる hook の責務で、hook はこの skill に同梱されない (Claude Code の設定側の資産で、配布経路が別)。hook が無い環境でもまとめを書く価値は変わらないが、自動では届かないので、書いたまとめのファイルの場所をユーザーに伝えて、集約先へは手で渡してもらう。

## 手順

1. まとめの置き場を会話の中から探す。置き場のパスは hook の告知 (セッション開始時の告知、コミット後の案内) が与えるので、この skill は自分で決めない。見つからなければユーザーに聞く
2. まとめを書く前に、知見の出所のリポジトリ (作業中のリポジトリと、セッション中に触った他のリポジトリ) それぞれの公開範囲を `gh repo view --json visibility` で確かめる。確かめられなければ (gh が無い、失敗、空) 非公開として扱う。1つでも非公開か確かめられないものがあれば、まとめ全体を非公開として扱う。非公開のときは、固有名 (リポジトリ名、製品名、顧客名、人名) と案件の中身を書かない。他のリポジトリでも通じる形に一般化した知見だけを書く。秘密情報 (キー、トークン、認証情報、絶対パス、ユーザー名) は公開範囲によらず書かない
3. 全体に知見が1件も無ければ書かない。1件でもあれば、残りのセクションは「なし」と1行だけ書く
4. このスキルと同じディレクトリの `template.md` を読み、各セクションをコメントのガイドに従って埋め、置き場のファイルへ書き出す。まとめは丸ごと書き直してよい。既存のまとめがあれば読んでから、このセッションの全体を反映した最新の内容に置き換える
5. 締めは呼び出し元に従う。次の2つは呼び出し元ごとの分岐で、最後の1つは、どちらの経路でも該当すれば重ねて添える:
   - hook の告知や案内で呼ばれた: その文面が求める行動に従う。行動の canonical は hook 側にあり、ここに再掲しない
   - 手動依頼: 書き出した旨とファイルパスだけ報告する
   - どちらの経路でも、告知が見つからず hook の有無も分からないままユーザーに置き場を聞いたときは、「自動では届かないかもしれない。このファイルを集約先へ渡すこと」を添える

## 書き方の要点

- 埋める内容の構造は template.md が canonical。セクションの追加・削除はしない
- 集約先の箱へ直接書かない。届けるのは hook で、箱の場所や形はこの skill の関知しないところ
- 置き場の規則 (どこに置くか、いつ届けるか、案内を何回出すか) は hook が canonical で、この skill は受ける側なのでここには書かない。その hook はこの配布物の外にある。ここに値を写すと、hook の無い配布先では写した値だけが残って canonical に見える
- 各知見には確かめた度合い (実測 / ドキュメントのみ / 推測) を付ける。読み手は度合いで扱いを変える。「なし」の行には要らない
