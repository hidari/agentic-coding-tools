# Cross-Repo Learnings

リポジトリを越えて効く知見を、まとめのファイルに外部化する。この skill が持つのはまとめの書式と書き方まで。まとめを集約先へ届けるのは対になる hook の責務で、hook はこの skill に同梱されない (Claude Code の設定側の資産で、配布経路が別)。置き場の規則 (どこに置くか、いつ案内するか、何回案内するか) も hook が canonical で、ここには写さない。写すと、hook の無い配布先では写した値だけが残って canonical に見える。hook が無い環境でもまとめを書く価値は変わらないが、自動では届かないので、書いたまとめのファイルの場所をユーザーに伝えて、集約先へは手で渡してもらう。

## 手順

1. まとめの置き場を会話の中から探す。置き場のパスは hook の告知や案内が与えるので、この skill は自分で決めない。見つからなければユーザーに聞く
2. このセッションで、リポジトリを越えて効く知見が1件でも出たかを判定する。1件も無ければここで終える (書かない。公開範囲の確認にも進まない)
3. 知見の出所のリポジトリ (作業中のリポジトリと、セッション中に触った他のリポジトリ) ごとに、そのディレクトリで `gh repo view --json visibility` を実行するか、`gh repo view <owner/repo> --json visibility` の形で公開範囲を確かめる。引数なしの実行は cwd のリポジトリしか見ない。PUBLIC だけを公開として扱い、それ以外 (INTERNAL を含む) と確かめられなかったもの (gh が無い、失敗、空) は非公開として扱う。1つでも非公開があればまとめ全体を非公開として扱う
4. 非公開のときは、固有名 (リポジトリ名、製品名、顧客名、人名) と案件の中身を書かず、他のリポジトリでも通じる形に一般化した知見だけを書く。秘密情報 (キー、トークン、認証情報、絶対パス、ユーザー名) は公開範囲によらず書かない
5. このスキルと同じディレクトリの `template.md` を読み、各セクションを埋めて置き場のファイルへ書き出す。template.md の HTML コメントは消す。知見の無いセクションは「なし」と1行だけ書く。まとめは丸ごと書き直してよい。既存のまとめがあれば読んでから、このセッションの全体を反映した最新の内容に置き換える
6. 締めは呼び出し元に従う:
   - hook の告知や案内で呼ばれた: その文面が求める行動に従う。行動の canonical は hook 側にあり、ここに再掲しない
   - 手動依頼: 書き出した旨とファイルパスだけ報告する。手順 2 で終えたときは「書くものが無かった」と伝える
   - どちらの経路でも、告知が見つからず hook の有無も分からないままユーザーに置き場を聞いたときは、「自動では届かないかもしれない。このファイルを集約先へ渡すこと」を添える

## 書き方の要点

- 埋める内容の構造は template.md が canonical。セクションの追加・削除はしない
- 集約先へ直接書かない。届けるのは hook
- 各知見には template.md の行の形で確かめた度合いを付ける。読み手は度合いで扱いを変える。「なし」の行には要らない
