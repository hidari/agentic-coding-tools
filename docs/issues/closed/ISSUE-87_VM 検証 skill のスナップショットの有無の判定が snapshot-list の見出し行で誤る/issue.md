# fix: VM 検証 skill のスナップショットの有無の判定が snapshot-list の見出し行で誤る

## 背景

ISSUE-85 で macos-vm-verification と windows-vm-verification に足した「検証 VM の扱い (スナップショットと停止)」の手順は、スナップショットの有無を `prlctl snapshot-list "<vm>"` の出力が「空」かどうかで判定している。手順 1 (既存のスナップショットがあればユーザーへ確かめる) と手順 6 (報告の前に作業で取ったものが残っていないことを確かめる) の 2 箇所である。

ところが `prlctl snapshot-list` は、スナップショットが 0 件でも見出しの行を 1 行出す。出力は字義どおりには空にならないので、手順 1 はスナップショットの無い VM でも毎回ユーザーへ確かめに行き、手順 6 は片付けが済んでいても確認に失敗しうる。v0.13.0 のリリースノートを消費側の目で読んだ批評役が見つけた。

## 確かめたこと (2026-10-01)

- このリポジトリの側で、手元の 2 台 (macOS と Windows) に `prlctl snapshot-list "<vm>"` を読み取りだけで当てた。2 台ともスナップショットは 0 件で、どちらも rc=0、出力は見出しの 1 行だった
- dotfiles 側でも再現した。2 台とも停止していてスナップショットは 0 件で、素の `snapshot-list` は rc=0 で見出しの 1 行、`-H` (`--no-header`) を付けると rc=0 で 0 行だった
- 手順 2 は、取ったスナップショットの ID を控えるのに `snapshot-list` を使っている。こちらは見出しがあった方が列を読み違えにくいので、判定の 2 箇所とは扱いを分けてよい

## 実機で通した結果 (2026-10-01、dotfiles 側)

dotfiles 側で、手順の prlctl の一連を macOS の VM (Apple の仮想化で動く APPLE_VZ_VM) と Windows の VM の両方で実機に通した。2 台とも最後はスナップショット 0 件、停止の状態で終えてある。

- snapshot は 2 台とも、停止中でも起動中でも rc=0 で取れた。APPLE_VZ_VM でも取れる
- snapshot-switch で原状へ戻ることを、ゲストに目印のファイルを作ってから戻し、再起動したゲストで目印が無いことで確かめた
- snapshot-delete は、途中のスナップショット (子) と原状保全 (親) の 2 件とも rc=0 で消えた

手順 5 (停止) について、文面に効く発見が 2 つあった。

- 原状保全を停止中に取ると、手順 4 の snapshot-switch の時点で VM は停止している。続く手順 5 の `prlctl stop` は、stderr に「VM が起動していないので止められない」旨の Failed を出しながら rc=0 を返す (2 台とも。存在しない VM 名では rc=255 なので、終了コードの取り方の問題ではない)。害は無いが、Failed を見たエージェントが迷う
- macOS の VM は素の `prlctl stop` で止まらない。起動中の VM に打つと「Operation canceled」の Failed で rc=255 になり、VM は起動したまま残る (2 回中 2 回。起動しきってから打っても同じ)。`prlctl stop --kill` なら rc=0 で停止する。Windows の VM は素の stop で rc=0 で停止した。原因は確かめていない

## 決めたこと

- 手順 1 と手順 6 の判定は、どちらも `prlctl snapshot-list "<vm>" -H` の出力が空であることに揃える。「見出し以外の行が無い」と散文で書くより機械的に判定できる (dotfiles 側の判断に同意)
- `-H` は VM 名の後ろに置く。直す途中で VM 名の前に置いた形を書いたところ、2 台とも Unrecognized option で rc=255 になった (prlctl 27.0.2 で実測)。前に置くと VM 名がオプションとして読まれる。dotfiles 側の確認は後ろに置いた形で、rc=0 の 0 行だった。手順 1 にこの理由を添える
- 手順 5 は、`prlctl list -a` で VM が起動しているときだけ止める。停止中の VM へ stop を打たないので、Failed の出力に迷う場面が無くなる
- macos-vm-verification の手順 5 は `prlctl stop "<vm>" --kill` で止める。手順 4 で原状へ戻した後なので、強制停止で失うものは無い。windows-vm-verification は素の stop のままにする (実機で止まることを確かめてあり、強制停止にする理由が無い)

## 見送ったこと

- 手順 5 は `running` のときだけ止めるので、手順 4 の後に一時停止 (suspended や paused) の VM は止めず、手順 6 の `stopped` の確認で引っかかる。マージ前ゲートの指摘で、手順 5 を「`stopped` でなければ止める」形にする案が出た。一時停止の VM に対する `prlctl stop` の挙動は実機で測っていないので、測らないまま手順に書かずに見送った。手順 6 で引っかかれば、エージェントは報告の前に止まって気づける
