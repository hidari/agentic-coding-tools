# fix: jev-lint-curated のキー付き実行の案内を打てる形にし要約に対象の一覧を出す

## 背景

SKILL.md はキー付きの実行をユーザーに `!` で打たせ、エージェントにはキーを読む・尋ねることを禁じている。ところが示している形は、そのままでは打てない。

- キーを取り出す部分が `<...>` のプレースホルダで、置き換えずに打つと zsh は `<` をリダイレクトとして読み、parse error で止まる。置き換える前提が案内の中で伝わっていない
- スクリプトの位置が `${CLAUDE_SKILL_DIR}` のままだと、ユーザーのシェルではこの変数が空になり `/scripts/jevlint.py` を指す
- 秘密情報の管理ツールによっては、キーを取り出すコマンドにアカウントなどの指定が要る

消費側では、parse error のあとエージェントが打てる形を作ろうとして、キーの置き場所をユーザーに尋ね、キーの所在を調べ、個人の識別子をチャットに書いた。境界を課しながら、そのままでは打てない案内しか渡していないので、打てる形にしようとするとエージェントは境界を越えるしかなかった。直すのは skill の設計の側で、エージェントを縛る文を足すだけでは済ませない。

もう 1 つ、実行の要約は degraded の件数と、関連テストが無く見送った paired の件数だけを出し、どの対象かを出さない。記録の JSON は一時ディレクトリにあって実行後に消えるので、中身を確かめる手段が無かった。

## タスク

- [x] キー付き実行の案内を、ユーザーがキーを取り出す部分だけを埋めればそのまま打てる形にする。埋める前でもシェルの構文として壊れず、埋めずに打つと送る前に止まる形にし、埋め方を案内の直後に書く
- [x] 案内のスクリプトの位置と対象のパスを、エージェントが展開した値で示すと書く
- [x] 境界の節に、キー付き実行が失敗してもエージェントはキーの所在の調査・確認・読み出しに進まず、コマンドの形の問題だけを指摘すると書く
- [x] 実行の要約に、degraded になった対象と、関連テストが無く見送った対象の一覧を出す
