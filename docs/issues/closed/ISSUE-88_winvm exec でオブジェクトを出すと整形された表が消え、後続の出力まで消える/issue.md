# fix: winvm exec でオブジェクトを出すと整形された表が消え、後続の出力まで消える

## 背景

dotfiles 側で VM 検証 skill の手順を実機の Windows VM で通したとき (ISSUE-87 の判断材料) に見つかった。`winvm exec` でオブジェクトをそのまま出力すると、表示が失われたまま rc 0 で返る。失敗がエラーではなく「出力が無い成功」として返るので、検証の結果を読み違える。

## 確かめたこと (2026-10-01、dotfiles 側の報告)

- `Get-Item ... | Select-Object Name,Length` のようにオブジェクトをそのまま出すと、整形された表が改行 (`\r\n`) だけになって消え、rc 0 を返す
- それがスクリプトの先頭にあると、後ろに続く `Get-Content` の文字列の出力まで消える
- `| Out-String` を付けると全部出る

## 再現と機構 (2026-10-01、こちらの Windows VM で測った)

同じ `winvm exec` の経路で、形だけを変えて流した。

- オブジェクトを先、`Get-Content` を後にすると、どちらも消えて rc 0 (報告どおり)
- 末尾で 600ms 待っても消える。整形の待ち時間の問題ではない
- 文字列を先、オブジェクトを後にすると、文字列は出てオブジェクトだけが消える。オブジェクトが出た時点から後の出力が捨てられる
- ラッパの .ps1 から行を 1 つずつ外して流すと、末尾の `exit` を外した形と、コマンドを `| Out-Default` に通してから `exit` する形だけで出た。`[Console]::OutputEncoding` の行は関係しない

機構: 既定の出力の整形はパイプラインの終わりで吐き出される。ラッパは終了コードを伝えるために末尾で `exit` するので、整形が吐き出される前にスクリプトが終わり、表とそれより後の出力が捨てられていた。コマンドの中の `exit` と `throw` でも同じ形で消える。

## 直し方

winvm の側で直す。SKILL.md に `| Out-String` を付ける規定を書く形は、書き忘れたときに同じ「出力の無い成功」へ戻るので採らない。

採った形では、.ps1 が自分自身を 2 回使う。

- 外側は自分を `-WinvmInner` 付きで呼び直し、その出力を `Out-String -Stream -Width 4096` で文字列にしてから `exit` する。`Out-Default` にしないのは、host に任せると表の見出しに色の制御文字が混ざるため (VM で実測。health と同じ選択)。`-Width` が無いと host の幅を超えた表の列がエラー無しで落ちる
- 内側でコマンドを動かす。呼び直したスクリプトの中の `exit` と `return` は内側だけを終わらせるので、外側のパイプラインは最後まで流れて出力が残る
- `return` で抜けると `$?` を渡す行が走らないので、外側は成功を初期値にする
- コマンドの中の `break` と `continue` は、呼び直したスクリプトを飛び越えて外側で最も近いループまで抜ける。ループが無いと外側のスクリプトごと終わり、終了コードの伝搬も表も失われる。呼び出しを 1 回だけ回るループで包み、そこで止める
- 呼び出しを try/catch で包まない。ループは handler ではないので、下の 2 つ目の形で起きた格上げは起きない

ここへ至るまでに 3 回作り直した。どれもマージ前ゲートの指摘による。

- 最初の形は、コマンドをブロックで包んで `Out-String -Stream` に通すだけだった。トップレベルの `return` でブロックだけを抜けて `$?` を渡す行が走らず、成功がエラーの無い rc 1 になった。`-Width` が無く、表の列が幅で落ちた。コマンドの中の `exit 0` の手前の表も消えたままだった
- 2 つ目の形は、自分自身を `-WinvmInner` 付きで呼び直す形 (`-Width` と成功の初期値もここで入った) で、その呼び出しをさらに try/catch で包み、`throw` の手前の表も残そうとした。ところが try/catch が呼び出しの経路に乗ると、PowerShell は文だけを止めるエラー (コマンドが無い、.NET の例外、パラメータの不一致など) をスクリプト全体を止めるエラーへ格上げし、コマンドの続きが走らなくなった (手元の pwsh で、素のスクリプトと比べて実測)。`git --version; cargo --version` の片方が無いだけで残りが走らない形になるので、try/catch を外した
- 3 つ目の形 (try/catch を外しただけ) では、コマンドの中の `break` / `continue` が外側のスクリプトごと終わらせ、native の `exit 3` の後の `break` が rc 0 になり、表も消えた。この Issue より前の形でも同じだったが、この Issue が消したい「出力の無い成功」そのものなので、1 回だけ回るループで包んで塞いだ

既知の限界:

- コマンドが `throw` すると、それより前に出したオブジェクトの表は消える。素のスクリプトでも同じで、rc 1 とエラーが出るので出力の無い成功にはならない
- コマンドの先頭の `param()` はコマンドの呼び出しとして扱われ、エラーを出して続きが走る。`using` 文は先頭に置けないので parse error になる。どちらも、コマンドがスクリプトの先頭に来ない包み方である限り避けられず、この Issue より前の形でも同じだった
- native コマンドの標準出力も `Out-String` を通るので、UTF-8 として読めないバイトは置換文字になり、単独の CR は改行になる (手元の pwsh で実測)。VM の cmd は UTF-8 で書くので、`cmd /c echo` の日本語や `dir /?` の出力は、この Issue より前の形とバイトまで一致した
- 内側から見える `$MyInvocation`、`$PSBoundParameters`、`$input` は呼び直しのものになる。トップレベルの `Write-Error` のエラーは、呼び直しの行を位置として示す

## 確かめたこと (直したあと)

手元の pwsh 7.6.4 で、素のスクリプトと採った形に同じコマンドを流して比べた。既知の限界に挙げたものを除けば、素のスクリプトとの違いは意図したものだけだった: `exit` と `break` の手前のオブジェクトの表が残る、native と cmdlet の失敗が rc に伝わる、色の制御文字が混ざらない、幅の広い表の列が落ちない。文だけを止めるエラーの後に続きが走ること、`$ErrorActionPreference = 'Stop'` で止まること、`throw` で rc 1 になり手前の表が消えることは、素のスクリプトと同じだった。

そのうえで、直した winvm.py を full chain (scp、`pwsh -File`、後始末) で Windows VM に通した。VM 検証 skill の手順どおり原状保全を取ってから流し、最後は原状へ戻してスナップショット 0 件、停止で終えた。

| コマンド | rc | 標準出力 |
|---|---|---|
| オブジェクトの後に `Get-Content` (報告の形) | 0 | 表と 2 行 |
| `cmd /c exit 3` | 3 | 無し |
| 存在しないパスの `Get-Item` | 1 | 無し (エラーは標準エラー) |
| 表の後に `throw` | 1 | 無し (エラーは標準エラー。既知の限界) |
| 表の後に `exit 0` | 0 | 表 |
| 表の後に `exit 5` | 5 | 表 |
| トップレベルの `return` | 0 | `return` の手前の 2 行 |
| 存在しないコマンドの後に `Write-Output` | 0 | 前後の 2 行 (エラーは標準エラー) |
| `1/0` の後に `Write-Output` | 0 | 前後の 2 行 (エラーは標準エラー) |
| `cmd /c exit 3` の後に `break` | 3 | 無し |
| 表と文字列の後に `break` | 0 | 表と文字列 |
| 表の後の `ForEach-Object` の中の `break` | 0 | 表と `break` の手前の 1 行 |
| 3 列とも 100 文字の表 | 0 | 3 列の見出しと値 (100 文字の値がそれぞれ 1 行に出た) |
