# fix: winvm exec でオブジェクトを出すと整形された表が消え、後続の出力まで消える

## 背景

dotfiles 側で VM 検証 skill の手順を実機の Windows VM で通したとき (ISSUE-87 の判断材料) に見つかった。`winvm exec` でオブジェクトをそのまま出力すると、表示が失われたまま rc 0 で返る。失敗がエラーではなく「出力が無い成功」として返るので、検証の結果を読み違える。

## 確かめたこと (2026-10-01、dotfiles 側の報告)

- `Get-Item ... | Select-Object Name,Length` のようにオブジェクトをそのまま出すと、整形された表が改行 (`\r\n`) だけになって消え、rc 0 を返す
- それがスクリプトの先頭にあると、後ろに続く `Get-Content` の文字列の出力まで消える
- `| Out-String` を付けると全部出る

## 再現と機構 (2026-10-01、こちらの Windows VM で測った)

同じ `winvm exec` の経路で、形だけを変えて流した。

- オブジェクトを先、`Get-Content` を後にすると、どちらも消えて rc 0 (報告どおり)
- 末尾で 600ms 待っても消える。整形の待ち時間の問題ではない
- 文字列を先、オブジェクトを後にすると、文字列は出てオブジェクトだけが消える。オブジェクトが出た時点から後の出力が捨てられる
- ラッパの .ps1 から行を 1 つずつ外して流すと、末尾の `exit` を外した形と、コマンドを `| Out-Default` に通してから `exit` する形だけで出た。`[Console]::OutputEncoding` の行は関係しない

機構: 既定の出力の整形はパイプラインの終わりで吐き出される。ラッパは終了コードを伝えるために末尾で `exit` するので、整形が吐き出される前にスクリプトが終わり、表とそれより後の出力が捨てられていた。コマンドの中の `exit` / `return` / `throw` でも同じ形で消える。

## 直し方

winvm の側で直す。SKILL.md に `| Out-String` を付ける規定を書く形は、書き忘れたときに同じ「出力の無い成功」へ戻るので採らない。

最初の直しは、コマンドをブロックで包んで `Out-String -Stream` に通す形だった。マージ前ゲートで 2 つの穴が見つかった。トップレベルの `return` でブロックだけを抜けて `$?` を渡す行が走らず、成功がエラーの無い rc 1 になる。`-Width` が無いと host の幅を超えた表の列がエラー無しで落ちる。コマンドの中の `exit 0` の手前の表も消えたままだった。

採った形では、.ps1 が自分自身を 2 回使う。

- 外側は自分を `-WinvmInner` 付きで呼び直し、その出力を `Out-String -Stream -Width 4096` で文字列にしてから `exit` する。`Out-Default` にしないのは、host に任せると表の見出しに色の制御文字が混ざるため (VM で実測。health と同じ選択)
- 内側でコマンドを動かす。呼び直したスクリプトの中の `exit` と `return` は内側だけを終わらせるので、外側のパイプラインは最後まで流れて出力が残る
- `return` で抜けると `$?` を渡す行が走らないので、外側は成功を初期値にする
- `throw` は外側の try/catch で受け、手前の出力を吐き出したあとでエラーを出して `exit 1` する

既知の限界: コマンドが `param()` で始まる形と `using` 文は、内側の if のブロックの中に置かれるので parse error になる。

## 確かめたこと (直したあと)

手元の pwsh 7.6.4 で、最初の直しと採った形に同じ 10 個のコマンドを流して比べ、採った形で全部が期待どおりになった。そのうえで、直した winvm.py を full chain (scp、`pwsh -File`、後始末) で Windows VM に通した。VM 検証 skill の手順どおり原状保全を取ってから流し、最後は原状へ戻してスナップショット 0 件、停止で終えた。

| コマンド | rc | 標準出力 |
|---|---|---|
| オブジェクトの後に `Get-Content` (報告の形) | 0 | 表と 2 行 |
| `cmd /c exit 3` | 3 | 無し |
| 存在しないパスの `Get-Item` | 1 | 無し (エラーは標準エラー) |
| 表の後に `throw` | 1 | 表 (エラーは標準エラー) |
| 表の後に `exit 0` | 0 | 表 |
| 表の後に `exit 5` | 5 | 表 |
| トップレベルの `return` | 0 | `return` の手前の 2 行 |
| 3 列とも 100 文字の表 | 0 | 表 |

幅の広い表で 3 列とも残ることは手元の pwsh で確かめた。VM では出力の先頭 200 文字だけを見た。
