# fix: --check が未追跡のファイルを見ず新しい issue.md の違反を素通りさせる

## 背景

出所は dotfiles のセッションから受けた skill の欠陥報告 (受け箱経由、2026-11-10)。

- 報告 (実測): in-repo-issue の記法の検査 (識別子の数字記法の混入) は未追跡のファイルを見ず、新しい issue.md に違反があっても「違反なし」を返した。`git add -N` の後で同じ検査が違反を 2 件出した。報告者の提案: 新規ファイルを検査の母集団に入れるか、未追跡があると告げる

### 本リポジトリでの再現 (2026-11-10)

`ISSUE-1_a` をコミットした git リポジトリに、未追跡の `ISSUE-2_b/issue.md` を置き、本文に数字記法 (`#12`) を書いて、skill 同梱の `issue-id.py --check` を回した。

| 状態 | 出力の要約行 | 結果 | rc |
|---|---|---|---|
| 未追跡のまま | 検査した Issue ディレクトリ: 2 個 / 走査したファイル: 1 個 | 違反なし | 0 |
| `git add -N` の後 | 検査した Issue ディレクトリ: 2 個 / 走査したファイル: 2 個 | 違反 1 件 | 1 |

ディレクトリ名の検査は filesystem を見るので未追跡の `ISSUE-2_b` も数えるが、本文の走査は `git ls-files` の追跡ファイルだけを読む。要約行は Issue ディレクトリ 2 個に対して走査したファイル 1 個とずれを出しているのに、結果は緑になる。

起票の直後 (A.2 で `cp` した issue.md を編集し、まだ `git add` していない状態) に手で `--check` を回すと、この形を踏む。pre-commit から回すときは staged のファイルが追跡下に入るので踏まない。

## 決めたこと (2026-11-11)

Hidari の判断で (a) にした。本文の走査に、Issue ディレクトリ配下の未追跡で ignore されていないファイルを加える。Issue ディレクトリの数え上げ (filesystem を見る) と本文の走査の母集団が揃い、要約行のずれも消える。入口は増やさず、git の呼び出しを 1 本足すだけにした。

- 引き受けたこと: pre-commit は未追跡のファイルを stash しないので、違反のある書きかけの issue.md を git add せずに置いているあいだは、無関係なコミットでも hook が赤くなる。issue-id.py の docstring の「既知の限界」に書いた
- (b) は起票してから git add するまで全てのコミットを止めるので採らなかった。(d) として検討した「名指しだけして rc を変えない」は、緑のまま読み手が気づくかどうかに頼るので採らなかった
- --check-diff が未追跡を数えない非対称はそのまま残した。--check-diff は差分の後側 (index か HEAD) を見る入口で、--check は backstop として追跡前のものも見る、という既存の線引きに沿う
- intent-to-add (git add -N) のファイルは index にあるので `--others` に出ず、二重には数えない (テストで pin した)
