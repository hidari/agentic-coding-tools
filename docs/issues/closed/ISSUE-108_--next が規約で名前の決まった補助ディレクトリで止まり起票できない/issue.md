# fix: --next が規約で名前の決まった補助ディレクトリで止まり起票できない

## 背景

出所は dotfiles の受け箱に届く前の、別のリポジトリのセッションのまとめ (2026-11-12)。

- 報告 (実測): `docs/issues/` 直下に Issue の雛形の置き場と過去の資料の保管庫を持つリポジトリで、`--next` が rc 1 で止まった。stdout は空で、stderr は 2 つのディレクトリを「採番が数えられない Issue ディレクトリ」として報告した。出所は現ツリーと全 ref (main を含む 42 本)
- 報告 (実測): 2 つの置き場はそのリポジトリの規約が名前つきで決めているので、改名も移動もできない。出所が全 ref なので、作業ツリーで直しても main に入ってリモートの全ブランチが追いつくまで解けない。その間は、全 ref から番号の最大を手で拾って起票している
- 報告者の推測: 同じ版から例外の名前を固定値で持つ設計に変わった

### 確かめたこと (2026-11-12)

- 止まるようになったのは ISSUE-104 から。それより前の `--next` は、数えられない名前を黙って飛ばしていた。例外の名前が `templates/` と `closed/` だけなのはもっと前からで、変わったのは「飛ばす」が「止める」になったこと。報告者の推測は、向きは合っているが何が変わったかが違う
- 報告元の 2 つのディレクトリを全 ref で列挙した。中に採番が数える形 (`ANY_ISSUE_DIR`) の名前は無い。`issue.md` は雛形の 1 本だけ
- 形では見分けられない。雛形の置き場は `<置き場>/<雛形>/issue.md` の形を持ち、ISSUE-104 が止めたい「Issue をまとめたディレクトリ」(`closed/<年>/2-b/issue.md` など) と構造が同じになる

## 決定 (2026-11-12)

リポジトリの側で「Issue ではないディレクトリの名前」を宣言できるようにする。宣言の置き場と形の canonical は `issue-id.py` の docstring に置く。

- 宣言は作業ツリーのものを読み、全 ref の走査に同じものを当てる。ref ごとの宣言を読むと、42 本の ref が追いつくまで解けない元の問題がそのまま残る
- 宣言が無いときの振る舞いは今と同じにする (ISSUE-104 の保証を保つ)
- 宣言できる名前は、番号を隠しうるものを拒む。採番が数える形・`closed`・パス区切りを含むもの・数字で始まるものは宣言できない
- 宣言したディレクトリ (と `templates/`) の中に採番が数える形の名前があれば止める。宣言で外したものの中に Issue が残っていると、その番号を rc 0 で再発行する
- 入口は増やさない (ISSUE-21)。CLI のフラグではなくファイルを読む
- 名前の決め打ちは採らなかった。そのリポジトリだけの事情で、ほかの配布先でも同じ名前を黙って飛ばすことになる
- 警告に留めて rc 0 を返す案も採らなかった。ISSUE-104 が直した「黙って飛ばして番号を再発行する」形に戻る

- [x] 宣言で外したディレクトリの中に番号を持つ名前があれば止まることを pin する

### 通しの確認 (2026-11-12)

報告元の ref (ローカル 1 本と remote-tracking 41 本) をオブジェクト共有の clone へ写し、HEAD の作業ツリーで回した。

| 版 | 宣言 | `--next` の rc | 出力 |
|---|---|---|---|
| 変更前 | なし | 1 | 2 つのディレクトリを名指し |
| 変更後 | なし | 1 | 同じ 2 件 (ISSUE-104 の保証が残る) |
| 変更後 | 2 つの名前 | 0 | 全 ref の番号の最大を別の手順で数えた値の次と一致 |

`--check` では、宣言した 2 つの命名違反が 2 件から 0 件になった。保管庫の中の文書に書かれた GitHub の数字記法の違反は残る。宣言はディレクトリを Issue として数えるかだけを決め、ファイルの中身の走査からは外さない。中身の走査からパスを外す口は dotfiles の ISSUE-121 の範囲

## 関連

- ISSUE-104: 数えられない名前で `--next` を止めた変更。この Issue はその保証を保ったまま例外を足す
- ISSUE-63: 免除をプロジェクト側の設定で与える案。設定の置き場が未決で、ここで決める置き場に乗せられる
- ISSUE-21: `issue-id.py` の入口を増やさない注記
- dotfiles の ISSUE-121: 接頭辞と走査の除外を外から渡す計画。ここで作る宣言のファイルが、その置き場の最初の一歩になる
