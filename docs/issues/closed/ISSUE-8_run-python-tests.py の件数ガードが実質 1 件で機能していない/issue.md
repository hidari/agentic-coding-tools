# fix: run-python-tests.py の件数ガードが実質 1 件で機能していない

## 背景

PR #3 のマージ前レビュー中に気づいた。

`scripts/run-python-tests.py` は docstring で「0 件実行を緑と読まないための堰を 2 つ置く」と
宣言しており、その意図は正しい。しかし実装の下限は 0 件との比較しかない。

```python
# scripts/run-python-tests.py:60
if count == 0:
    return False, "0 件しか実行されていない (検査対象ゼロは合格ではない)"
```

現在 `test_winvm.py` は 144 件ある。このうち 143 件を消しても、残り 1 件が通れば緑になる。
守れているのは「収集が完全に壊れた」ケースだけで、「検査が痩せた」ケースは捕捉できない。

「0 件は健全ではなく、そもそも見ていない状態」という docstring の主張はそのとおりだが、
同じ理屈は「144 件が 3 件に減った」にも当てはまる。

### 先例

同じ構造の問題を Pester のラッパで踏んだことがある。最低件数の引数に既定値 1 を置いた
結果、呼び出し元がどこも指定せずガードが実質無効になっていた。そちらは引数を Mandatory に
して呼び出し元に件数を書かせる形で解決した。

その形が取れたのは呼び出し元が 1 箇所で件数が安定していたためで、ここは pre-commit と CI の
2 経路から呼ばれるので同じ手が使えるとは限らない。

## 検討事項

件数の下限を持つと、テストを増やすたびに数字の更新が要る。これは「値を 2 箇所に literal で
書かない」という方針と衝突しうるので、置き方を決める必要がある。

案:

- **A. ファイルごとの下限をスクリプト内の表に持つ**: 更新箇所が 1 つで済むが、
  テスト追加のたびに触る
- **B. 直近の件数を記録して減少時のみ落とす**: 記録ファイルが要る。増加は自動追随
- **C. 全体の下限を 1 つだけ持つ**: 粗いが更新頻度が低い

先例が Mandatory 引数で済んだ理由は上に書いたとおり呼び出し元が 1 箇所だったため。
ここは 2 経路から呼ばれるので、二重管理を避ける置き方を選ぶこと。

## タスク

- [x] A / B / C から方式を決める (二重管理にならないことを判定基準にする)
- [x] 実装する
- [x] 変異注入で確認する。3 種すべて見ること
      - 検査対象を壊す: テストを数件消して赤くなること
      - 検査機構を壊す: 下限比較を消して、それでも赤くなる経路が残っていないこと
      - 取り付けを外す: pre-commit と CI の両方から呼ばれていることを確かめる
        (片方だけ直して満足しない)

## 解決

A / B / C のいずれも採らず、**件数そのものを捨てた**。pin する対象を「実行されたテスト ID の
集合」に変え、`scripts/python-tests-manifest.txt` (機械生成、`--update-manifest` だけが書く)
と照合する形にした。

件数方式を全部落とした理由:

- **下限 (A / C)** は更新義務が無いので古びる。下限を割らない範囲の痩せは原理的に見えない
- **記録した件数との exact 一致 (B)** は古びないが、`test_a` を消して `test_b` を足す
  同数入れ替えと 1 件改名を検出できない
- **ID 集合**なら件数の literal がどこにも存在しなくなり、消えた側も未記録側も名指しで出る。
  更新コストは件数方式と同じ 1 コマンドで、検出力だけが上がる

件数では見えない痩せ方が他に 2 つあることも実測で分かったので、実行側で別途赤にしている。
`@unittest.skip` と `@unittest.expectedFailure` はどちらも `Ran N tests` に数えられ、
`wasSuccessful()` も True を返す。全テストを skip 化しても件数と exit code は変わらない。

あわせて、この Issue の周辺として挙がっていた「`scripts/` 配下が収集対象外」も塞いだ。
ディレクトリ列挙 (`SEARCH_DIRS`) をやめて ROOT 全体走査 + 除外列挙へ反転してある。
列挙方式は「列挙に無いディレクトリは無検査」という穴を、ディレクトリが増えるたびに
再発させる形だった。

### 残った限界

この検査は自分の取り付けを自分では検証できない。両取り付けの同時撤去・`__main__` ガードの
除去・集計を `return 0` に潰す変更は緑のまま素通りする (実測で確認済み)。CI へ第 2 の
取り付けを足せば塞がるが、取り付け literal の二重管理と引き換えになるため採っていない。

`scripts/` の他の検査スクリプトが無検査である件は
[Issue #12: scripts/ の検査スクリプトが自分自身のテストを持たない](../../ISSUE-12_scripts%20の検査スクリプトが自分自身のテストを持たない/issue.md)
へ分離した。

現在の canonical: 機構と限界は `scripts/run-python-tests.py` の docstring、
pin されている集合は `scripts/python-tests-manifest.txt`。
