# docs: VM 検証 skill に検証 VM のスナップショットと停止の扱いを書く

## 背景

windows-vm-verification と macos-vm-verification の SKILL.md は、検証 VM のスナップショットにも停止にも触れていない。消費側で検証を終えたエージェントが、VM を起動したまま、作業中に取ったスナップショットも残したまま報告する形が起きた。ユーザーの決定では、検証 VM は毎回、原状保全のスナップショットを取ってから作業し、原状へ戻したらその作業で取ったスナップショットを消し、停止してから報告する。

同じ作業で、Windows VM の GUI を UI Automation で自動操作したときの落とし穴を 3 つ踏んだ。日付入力が年・月・日の別々の要素に分かれること、画面遷移の直後に引いた要素が null になること、インストーラの実行がサービスの開始の種類を戻し、それ以降に取ったスナップショットへ焼き込まれること。

VM の CLI (winvm / macvm) にサブコマンドは足さない。足すと shell-out の live smoke に実機の VM が要る。手順として SKILL.md に書く。

## タスク

- [x] 2 つの SKILL.md に、検証 VM の扱いの順序 (作業前の原状保全のスナップショット、途中のスナップショット、原状へ戻したあとの削除、停止) と、報告の前の確認 (スナップショットの一覧が空で、VM が stopped) を書く
- [x] 作業前からあったスナップショットを消さないこと (一覧を作業前に記録し、消すのは自分が取ったものだけ) を書く
- [x] Windows の GUI 自動操作の落とし穴 3 件を windows-vm-verification の references へ入れ、SKILL.md から辿れるようにする
