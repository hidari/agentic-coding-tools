# feat: in-repo-issue にタスクを消化せずに閉じる経路と閉じた理由の節の規約が無い

## 背景

`dev-workflow:in-repo-issue` が閉じる経路として持つのは、`## タスク` を全部消化したとき (Phase C / D) と、子が全部 closed になったとき (Phase E) の 2 つだけである。タスクを消化しないまま閉じる判断を下したときに従う手順が無く、閉じた理由を本文のどこにどう書くかの規約も、skill とテンプレートのどちらにも無い。C.3 は「チェックリスト未定義」「箱が空」の Issue に手動 close を勧めるが、その手動 close も手順を持たない。

配布先のリポジトリから、閉じる判断が 3 つの形で出て、どれも既存の経路に当てはまらず手で組んだという報告が届いた (経緯は dotfiles の ISSUE-129 が持つ)。

- 子を外して親を閉じる: 親の `children` と子の `parent` の両方から外し、親の `## タスク` の該当行の扱いを決める必要があった
- 別の置き場へ移して閉じる: 吸収先の Issue へ寄せるか、プロジェクトの別の置き場へ移すかの基準が無かった
- 見送りで閉じる: タスクは未チェックのまま残る

dotfiles の `closed/` では、未チェックのタスクを残して閉じた 10 件の理由の節が 2 系統の書き方に 5 件ずつ割れている。

## 実測 (2026-10-21)

`scripts/check-issue-closure.py` に fixture を通した。

| 形 | rc | 出力 |
| --- | --- | --- |
| 対照: active で箱が全て `[x]` | 1 | 不変条件 A の違反 |
| closed/ に未チェックの箱が残る | 0 | 違反なし (closed 1 個を数えている) |
| 子を外すとき子の `parent` だけ残す | 1 | 親子リンクが片側にしか無い |
| 子を外すとき親の `children` だけ残す | 1 | 親子リンクが片側にしか無い |
| 両側を外す | 0 | 違反なし |
| 外さずに親だけ closed、子は active | 0 | 違反なし (逆向きは見ない。ISSUE-45 の射程) |
| 子を外し親の行も消す。親 active、残りの子は全て closed | 1 | 不変条件 A と C がどちらも親の close を要求 |
| 同上で親の行を未チェックのまま残す | 1 | 不変条件 C だけが親の close を要求 |
| 最後の子を外して `children: []` を残す | 0 | 親子リンク 0 組 |

未チェックのまま closed/ へ移した Issue は、どの不変条件にも拒否されない。このリポジトリの `closed/` 40 件は全てタスク節と箱を持ち、未チェックは 0 件。

## タスク

- [x] 消化せずに閉じる経路の形と、閉じた理由の節の名前・置き場所を決める
- [x] 子を外す手順 (両側のリンク、親の `## タスク` の行、親の完了の定義から外したかの記録) を決める。ISSUE-45 と Phase E の両方と矛盾しない形にする
- [x] SKILL.md へ入れる。closed ならタスクは全消化という前提に立つ記述 (F.0 など) を直す
- [x] 未チェックのまま closed/ にある Issue を `scripts/check-issue-closure.py` がどう扱うかを決める

## 関連

- dotfiles の ISSUE-129: 報告を受けた dotfiles 側の受け口。経緯と報告者の提案を持つ
- ISSUE-45: 不変条件 A が親の箱を判定に使い、Phase E が使わない件。子を外す手順で親の箱の扱いを決めるときに重なる
- ISSUE-46: Phase E の子探索が空振りしたとき親の close 提案側へ倒れる。子を外す操作は親の `children` を書き換えるので、空振りの形 (`children: []` など) を作らないこと
- ISSUE-38: Phase E の親伝播が frontmatter の乖離で静かに発火しない
