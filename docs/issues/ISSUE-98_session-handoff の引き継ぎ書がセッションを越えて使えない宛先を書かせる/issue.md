# docs: session-handoff の引き継ぎ書がセッションを越えて使えない宛先を書かせる

## 背景

出所は dotfiles の ISSUE-132 (受け箱に届いた skill の改善提案) の session-handoff の 2 節。どちらも別のリポジトリのセッションの申告で、本リポジトリでは再現していない。

`session-handoff` の SKILL.md と template.md は、前のセッションの中でしか通じない宛先 (実行中の subagent の id、cross-session の相手のセッション名) をどう書くかを何も言っていない。どちらも引き継ぎ書を読んだ側からは使えない宛先として残り、使えないことは送ってみるまで分からない。

## 報告

### 実行中の subagent はセッションを越えて resume できない

- 報告 (実測): subagent の agent id は前のセッションの中のプロセスにしか届かず、新しいセッションの一覧には出ない。引き継ぎ書に「同じ implementer を resume する」と書いても使えない。報告元は、作業木の未コミットの変更をコントローラが全文読み、テストとゲートを回してから wip でコミットし、残り (変異注入と報告) だけを新しい subagent に渡した。復元先が HEAD になるので変異の復元も安全になった
- 報告者の提案: 「実行中の subagent はセッションを越えて resume できない。止めた subagent の続きは、新しい subagent 向けの brief として書き残す」を加える

### cross-session の相手をセッション名で書かせない

- 報告 (実測): handoff に書いた cross-session の相手のセッション名が、引き継いだ時点では別の名前になっていた。セッション名はセッションごとに変わる
- 報告者の提案: 相手をセッション名で書かせず、「送る直前に ListAgents で引く」と書かせる
- dotfiles で確かめたこと (2026-10-23): 別のリポジトリのセッションから dotfiles の前のセッションへ宛てた返信が、「宛先のソケットが消えていた」として次のセッションへ届いた。宛先の名前は前のセッションが依頼したときのもの。届け先をどう見つけたかは送り手が書いていないので分からない

## タスク

- [ ] 実行中の subagent を引き継ぐときは resume ではなく新しい subagent 向けの brief として書く、という指示を SKILL.md か template.md に足す
- [ ] cross-session の相手をセッション名ではなく見つけ方 (どのリポジトリのセッションか、送る直前に ListAgents で引く) で書かせる指示を足す
