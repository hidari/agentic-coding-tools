# fix: Issue 間の相対リンクの書式が 3 通り混在している

## 背景

`docs/issues/` 配下の Issue が互いを参照するとき、`## 関連` 節の書き方が揃っていない。
どの形も読めるので実害は見えにくいが、揺れは 2 軸ある。

## 実測 (2026-08-24)

`## 関連` 節を持つ 23 件を走査した。

### 軸 1: 半角空白を含むパスの書き方

Issue のディレクトリ名はタイトル部を含むので、半角空白を持つものが多い。その空白の扱いが
分かれている。空白を含まないパスは素のまま書かれていて、こちらは揺れようがない。

| 書き方 | 件数 | 該当 |
|---|---|---|
| 山括弧で囲う | 2 | ISSUE-14, ISSUE-23 |
| 空白を `%20` へ置換 | 7 | ISSUE-4, ISSUE-8, ISSUE-9, ISSUE-10, ISSUE-11, ISSUE-12, ISSUE-13 |
| リンクを張らず識別子だけ書く | 8 | ISSUE-15 から ISSUE-22 |

ISSUE-4 は同じ節の中で素のパスと `%20` 形の両方を使っている。つまりファイル単位で統一されて
いるわけでもない。

### 軸 2: リンクテキストの書き方

同じ走査で 4 通りが出た。

- 識別子だけ
- 識別子 + closed かどうか
- 識別子 + closed かどうか + タイトル全文
- リンク自体を張らず、識別子と説明だけを書く

### 計測を 1 回外した

最初の計測は「リンクを張らない」を 0 件と報告した。裸識別子を拾う正規表現に `re.MULTILINE` を
付け忘れていたためで、行頭アンカーが文字列の先頭にしかマッチしていなかった。

**陽性対照はこれを検出しなかった。**対照として渡したのが 1 行だけの文字列だったので、`^` が
狙った機構ではなく文字列先頭という別経路で成立していた。対照を「節見出しに続く行」という
検証対象と同じ構造上の位置へ置き直したところ、8 件が現れた。

## 何が問題か

- **リンクを張らない形は辿れない。**識別子は書いてあるので人間は探せるが、ディレクトリ名を
  知らないと開けない。Issue 間の導線がそこで切れる
- **`%20` 形はクローズ時の補正と噛み合わない。**Issue を `closed/` へ移す手順は相対リンクを
  3 方向について直すが、置換の対象はディレクトリ名である。`%20` 形は本文中の文字列が
  ディレクトリ名と一致しないので、手で直すときに揃え損ねる
- **軸 2 の「タイトル全文」形は冗長で、しかも同期先が無い。**ディレクトリ名のタイトル部は
  後から変えられない (採番スクリプトが同じ番号の別名を重複と見て止まる) ので drift はしにくいが、
  参照側にタイトルを持つ理由も無い

## どこで決めるか

規約の canonical は `dev-workflow:in-repo-issue` skill が持つ。同 skill は既に、パスに半角空白や
日本語を含むと Markdown リンクが山括弧形式で書かれることを前提にしていて (クローズ時の補正
パターンが山括弧を任意にしている)、`#` を含むパスについては URL エンコードせず素のパスでよいと
書いている。方向は示されているが、`## 関連` 節の書式としては明文化されていない。

決めたら散文ではなく検査へ落とせないかを先に検討すること。書式は機械検証できるので、規約を
散文に書くだけでは同じ揺れが再発する。
