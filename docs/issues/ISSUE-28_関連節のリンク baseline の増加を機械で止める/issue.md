# fix: 関連節のリンク baseline の増加を機械で止める

## 背景

`scripts/check-related-refs.py` は `## 関連` 節に残るローカルリンクの本数を `LINK_BASELINE` に
記録し、実態と突き合わせている。減った側は「baseline も同じ値へ下げること」として報告するので、
リンクを外したのに記録を残す形は止まる。

止まらないのは増える側。リンクを 1 本足して同じコミットで `LINK_BASELINE` を 1 増やすと、実態と
記録が一致するので違反 0 件の緑で通る。ISSUE-24 の裁定は「既存のリンクは baseline に記録して
触ったついでに減らす」、つまり単調非増加を前提にしているが、それを守っているのはレビューであって
検査ではない。

上限の側を書き換えれば通る形は配布先リポジトリでも踏んでいる。あちらの常時ロード量の予算検査は
超過のたびに上限を引き上げて 2 度通しており、その反省から `origin/main` の値と突き合わせる
ラチェットを後付けした経緯がある。

## 決めること

`origin/main` の `LINK_BASELINE` と突き合わせる形を採るかどうか。採る場合、CI の checkout から
`origin/main` が引けるかを先に実測する必要がある。`actions/checkout` の既定は `fetch-depth: 1`
で、`pull_request` イベントでは merge ref を取るため `origin/main` が存在しない可能性がある
(未実測)。

引けないときの代替は 2 つある。1 つは baseline の合計値を別ファイルへ持ち、変更に 2 箇所の
編集を要求して diff に必ず現れるようにする形。もう 1 つは既存リンクを一括で外して baseline を
空にする形で、こちらは ISSUE-24 が「一括変換はしない」と裁定済みなので、採るなら裁定の変更に
あたる。
