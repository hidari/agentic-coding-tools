# fix: 数字記法の検出が数字の直後の日本語で素通りする

## 背景

`in-repo-issue` の `scripts/issue-id.py` は、GitHub の数字記法 (`#` に数字が続く形) が追跡ファイルやコミットメッセージに混ざることを検出する。パターン `GITHUB_REF` は数字の後ろを `\b` で区切っている。Python の `re` は既定で Unicode の単語文字を使い、ひらがなと漢字も単語文字に入るので、数字の直後にかな漢字が続くと境界が成立せず、一致しない。

数字の前後に空白を入れない書き方では、数字記法を書くとちょうどこの形になる。ISSUE-58の Task 5で、新しく書いた文の数字の前後の空白を詰めたときに、修正担当が見つけた。

`scripts/check-related-refs.py` は数字記法の判定にこの `GITHUB_REF` をそのまま借りている (同スクリプトの docstring) ので、同じ形で素通りするはずだが、測ってはいない。

## 確かめたこと (2026-09-25)

1行ずつファイルに書き、`issue-id.py --check-text` に通した。

| 行 | 結果 |
|---|---|
| `詳細は #52 を見る` | 違反1件 (rc 1) |
| `詳細は #52を見る` | 違反0件 (rc 0) |
| `詳細は #52件目` | 違反0件 (rc 0) |
| `詳細は #52。` と `詳細は #52、次` | 違反1件 (rc 1) |
| `詳細は #52-x` と `詳細は (#52)` | 違反1件 (rc 1) |
| `詳細は #52abc` と `詳細は #52_x` | 違反0件 (rc 0) |

後ろに空白・句読点・`-`・`)` が続く形は検出され、ひらがなと漢字が続く形だけが素通りする。`#52abc` と `#52_x` が素通りするのは、GitHub の参照の形ではないものを外すという `\b` の目的どおりと読める。

GitHub が `#52を` のような形を参照としてリンクするかは確かめていない。リンクしなくても読み手は GitHub の番号として読むので、記法を分けている目的 (in-repo Issue の識別子との混同を防ぐ) からは検出したい形である。

なお、インラインのコードとフェンスの中の数字記法は、どちらも検査の対象外だった (同じ行をコードの外に書くと違反1件)。上の表の例はそのために検出されない。

## 直し方の候補 (未検証)

- 後ろの境界を ASCII の単語文字で判定する (`(?![0-9A-Za-z_])` のような否定の先読み)。かな漢字が続く形を拾い、`#52abc` と `#52_x` は今までどおり外れる
- 配布先はプロジェクトへ写した `issue-id.py` を持つ (`in-repo-issue` の「初期化」節) ので、直しても写しは古いまま残る。取り付けの側の話は ISSUE-32 が扱う
