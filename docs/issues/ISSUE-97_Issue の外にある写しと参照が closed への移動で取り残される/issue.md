# docs: Issue の外にある写しと参照が closed への移動で取り残される

## 背景

出所は dotfiles の ISSUE-132 (受け箱に届いた skill の改善提案) の「in-repo-issue: Issue の外にある写しと参照」節。どれも別のリポジトリのセッションの申告で、本リポジトリでも dotfiles でも再現していない。

`dev-workflow:in-repo-issue` の Phase D.3 は、Issue を `closed/` へ移したときに壊れる相対リンクを補正する。補正の対象を探す grep は `--include='*.md'` で Markdown だけを見ているので、Markdown の外から Issue ディレクトリを指す参照は数えない。Issue の所在を別の場所へ写す形 (ロードマップのチェックボックスなど) についても、skill は何も言っていない。

## 報告

- 報告 (実測): Makefile の target などが Issue ディレクトリの中のファイルを glob で指していると、Issue を閉じて `closed/` へ移した時点で黙って見失う。報告者の提案: パスは変数 1 つにし、クローズの手順の相対リンクの補正と同じタイミングで道具側の参照も grep する
- 報告 (実測): in-repo Issue を初めて導入し、リリースまでのロードマップのチェックボックスを `closed/` の所在の写しとして置いて、写しと所在の食い違いを CI の検査で赤にした。順序と依存をロードマップと各 Issue の「前提」の両方に書くと起票の直後にもう食い違ったので、依存の canonical をロードマップ 1 箇所へ寄せた。報告者の提案: 箱を写しと位置づけて検査で赤にする形を雛形にし、「依存の canonical は 1 箇所に決める」指針を skill に足す

## タスク

- [ ] D.3 に、Markdown の外 (Makefile などの道具) から Issue ディレクトリを指す参照も探す手順を足すかを決める。足すなら探す範囲と grep の形を決める
- [ ] Issue の所在を写す箱を検査で赤にする形を雛形にするかを決める。雛形にしないなら、写すときは canonical を 1 箇所に決めるという指針だけを足すかを決める

- dotfiles の ISSUE-75: 写しの食い違いを config-guard で検査する前例。ロードマップを写しにする形と似ている
