# fix: run-python-tests.py の件数ガードが実質 1 件で機能していない

## 背景

PR #3 のマージ前レビュー中に気づいた。

`scripts/run-python-tests.py` は docstring で「0 件実行を緑と読まないための堰を 2 つ置く」と
宣言しており、その意図は正しい。しかし実装の下限は 0 件との比較しかない。

```python
# scripts/run-python-tests.py:60
if count == 0:
    return False, "0 件しか実行されていない (検査対象ゼロは合格ではない)"
```

現在 `test_winvm.py` は 144 件ある。このうち 143 件を消しても、残り 1 件が通れば緑になる。
守れているのは「収集が完全に壊れた」ケースだけで、「検査が痩せた」ケースは捕捉できない。

「0 件は健全ではなく、そもそも見ていない状態」という docstring の主張はそのとおりだが、
同じ理屈は「144 件が 3 件に減った」にも当てはまる。

### 先例

dotfiles の Issue #27 が `scripts/ci/run-pester.ps1` について同じ構造の問題を挙げている
(既定値 1 で、呼び出し元 2 箇所とも `-MinimumCount` を省略していた)。relay 側は
`-MinimumCount` を Mandatory にして呼び出し元に件数を書かせる形で解決している。

## 検討事項

件数の下限を持つと、テストを増やすたびに数字の更新が要る。これは「値を 2 箇所に literal で
書かない」という方針と衝突しうるので、置き方を決める必要がある。

案:

- **A. ファイルごとの下限をスクリプト内の表に持つ**: 更新箇所が 1 つで済むが、
  テスト追加のたびに触る
- **B. 直近の件数を記録して減少時のみ落とす**: 記録ファイルが要る。増加は自動追随
- **C. 全体の下限を 1 つだけ持つ**: 粗いが更新頻度が低い

relay が Mandatory 引数で解決しているのは、呼び出し元が 1 箇所で件数が安定しているため。
ここは pre-commit と CI の 2 経路から呼ばれるので、二重管理を避ける置き方を選ぶこと。

      - 検査機構を壊す: 下限比較を消して、それでも赤くなる経路が残っていないこと
      - 取り付けを外す: pre-commit と CI の両方から呼ばれていることを確かめる
