# refactor: session-handoff を機構ごと hook の隣へ戻すか決める

## 背景

ISSUE-23 の B2 で `session-handoff` skill の責務を「書き出し」へ縮め、hook の挙動の再掲を落とした。
これは配布物としての欠陥を閉じる変更だが、根本の構造は残っている。

この機構は設計時に 3 層 (検知 = hook / 手順 = SKILL.md / 書式 = template.md) を 1 機構として
設計されていた。それを「hooks は Claude Code の設定、skill はエージェント資産」というファイル
種別の境界で 2 リポジトリに割ったのが、経路数の drift や record の呼び出しが境界を越える形の
原因である。機能の境界ではなく種別の境界で割ったことによる。

代償は既に払われている。drift を扱う Issue が配布先リポジトリ側に複数ある。

## 何を決めるか

skill をこのリポジトリの配布対象から外し、hook の隣へ戻す案がある。実現には未実測の前提が 1 つ
ある。配布先で apm のローカルパス依存が lockfile と `--frozen` で通るかを確かめていない。

もう 1 つ、hook 側が provenance の記録を自分で行う形にして skill から hook のパスを完全に消す案も
ある。こちらは配布先リポジトリ側の変更になるので、決めるのはあちら側になる。

## タスク

- [ ] apm のローカルパス依存が lockfile と `--frozen` で通るかを実測する
- [ ] 戻すか残すかを決める。戻す場合はこのリポジトリからの削除と README 再生成を伴う
- [ ] hook 側が provenance を記録する形にするかを配布先リポジトリへ委譲する
