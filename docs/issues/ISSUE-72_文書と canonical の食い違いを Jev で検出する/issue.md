# feat: 文書と canonical の食い違いを Jev で検出する

## 背景

このリポジトリで繰り返し起きる欠陥は、コードのバグよりも「文書の記述が、別の文書・実装・検査器の実態と食い違う」型である (ISSUE-17、ISSUE-19、ISSUE-30、ISSUE-39、ISSUE-45、ISSUE-47、ISSUE-49、ISSUE-59、ISSUE-70)。形・命名・記法・識別子の実在は検査に落ちているが、散文の主張が canonical の実態と合っているかは、マージ前ゲートの LLM のレビューだけが見ている。レビューは費用が大きく、気軽には繰り返せない。

Jev (TypeSafe AI の採点 API) は型付きの確率だけを返し、安価で速いので、同じ観点を繰り返し回す網になりうる。jev-lint 0.7.0 には Markdown の節や文書全体を判定する rule の形があり、rule ごとに規約文書を添える `context:` もあるが、突き合わせる相手は rule に静的に書くしかない。散文が名指す canonical を引き当てて対にする段は無いので、この用途には自前の段が要る (0.7.0 のソースで確認)。

このリポジトリには、散文が canonical の所在を明示的に参照する (「canonical は X の docstring」、CLAUDE.md の canonical の表) という有利さがある。突き合わせる相手を推測ではなく参照から決められる。

実行の形と送る範囲は ISSUE-65 の「決めたこと」に従う。

## 分かっていること

- mizchi/jev-playground の対訳の実験 (`docs/28-bilingual.md`) では、文書全体を state に入れると欠落の検出が落ちた (1.84 から 0.57)。数値と識別子の違いは判断に渡さず、決定的な比較の側に置いている
- 同じ実験で、主張の強さを変えた変異 (hedge の強化) は見逃した (1例)
- 露骨な矛盾は日本語でも拾えることを、ISSUE-65 の陽性対照で確かめてある
- このリポジトリに多い「射程が微妙にずれる」型を拾えるかは未測定で、ここが成否を分ける
