# fix: VM 検証 skill のスナップショットの有無の判定が snapshot-list の見出し行で誤る

## 背景

ISSUE-85 で macos-vm-verification と windows-vm-verification に足した「検証 VM の扱い (スナップショットと停止)」の手順は、スナップショットの有無を `prlctl snapshot-list "<vm>"` の出力が「空」かどうかで判定している。手順 1 (既存のスナップショットがあればユーザーへ確かめる) と手順 6 (報告の前に作業で取ったものが残っていないことを確かめる) の 2 箇所である。

ところが `prlctl snapshot-list` は、スナップショットが 0 件でも見出しの行を 1 行出す。出力は字義どおりには空にならないので、手順 1 はスナップショットの無い VM でも毎回ユーザーへ確かめに行き、手順 6 は片付けが済んでいても確認に失敗しうる。v0.13.0 のリリースノートを消費側の目で読んだ批評役が見つけた。

## 確かめたこと (2026-10-01)

- このリポジトリの側で、手元の 2 台 (macOS と Windows) に `prlctl snapshot-list "<vm>"` を読み取りだけで当てた。2 台ともスナップショットは 0 件で、どちらも rc=0、出力は見出しの 1 行だった
- dotfiles 側でも再現した。2 台とも停止していてスナップショットは 0 件で、素の `snapshot-list` は rc=0 で見出しの 1 行、`-H` (`--no-header`) を付けると rc=0 で 0 行だった
- 手順 2 は、取ったスナップショットの ID を控えるのに `snapshot-list` を使っている。こちらは見出しがあった方が列を読み違えにくいので、判定の 2 箇所とは扱いを分けてよい

## 決めたこと

- 手順 1 と手順 6 の判定は、どちらも `prlctl snapshot-list -H "<vm>"` の出力が空であることに揃える。「見出し以外の行が無い」と散文で書くより機械的に判定できる (dotfiles 側の判断に同意)
