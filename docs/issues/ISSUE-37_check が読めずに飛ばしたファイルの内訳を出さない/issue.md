# fix: --check が読めずに飛ばしたファイルの内訳を出さない

## 背景

`issue-id.py --check` の要約は「読めずに飛ばした N」を件数だけで出す。どのファイルを飛ばしたかは
出力に現れないので、利用側は N の中身を自分で数え直さないと「違反 0 件」を完了判定に使えない。

飛ばす条件は `read_text(encoding="utf-8")` の `UnicodeDecodeError` と `OSError` である。
バイナリなら想定どおりだが、非 UTF-8 のテキスト (Shift_JIS など) が混ざっていた場合、その中の
数字記法は検査されないまま「飛ばした」に入る。件数だけでは両者を区別できない。

これは「その検査が実際に何を何件見たか」を出すという要約の目的を半分しか満たしていない。
走査した件数は出るが、走査しなかったものの正体が出ない。

## 実測 (2026-08-27)

配布先のリポジトリで検査を回したエージェントからの報告。

| 指標 | 値 |
| --- | --- |
| `--check` の走査ファイル | 849 |
| 読めずに飛ばした | 81 |
| 内訳 (利用側が `git ls-files` で数え直した) | PNG 80 / WOFF2 1 |
| 非 UTF-8 のテキスト | 0 |

この配布先に限れば全件バイナリだったので違反 0 件を完了判定に使えた。ただしそれを確かめるのに
利用側が別途スクリプトを書く必要があった。内訳が出ていれば要らない作業である。

## 検討

`--check` は追跡下の全ファイルを走査するので、飛ばした分を全部並べると出力が長くなりうる。
一方 `--check-diff` は差分だけなので件数が小さい。入口ごとに出し方を変えるか、
共通で「先頭 N 件 + 残り件数」の形にするかは実装時に決める。

`--check-diff` の要約も同じ構造で、`読めずに飛ばした` と `submodule` の内訳を持たない。
同じ手当てが要る。
