# fix: e2e skill が新たに読む置き場の規定が gate と関連節へ通っていない

## 背景

ISSUE-23 の B1 で `dev-workflow:e2e-scenario-impact-check` の判定条件からディレクトリ名を落とし、
UI と E2E の置き場を「呼び出し元から渡された値 → プロジェクトの CLAUDE.md の規定 → 内容で判定」の
順で決める形にした。この変更で 2 箇所が取り残されている。どちらも同じ変更に由来する。

**1. skip の根拠が呼び出し元へ届かない。** Phase 1 の skip 出力に「判定の根拠 (何を何件見たか)」を
足したが、`dev-workflow:pre-merge-quality-gate` の出力フォーマットは skip 理由を
`skipped (reason: ...)` の 1 行で受ける形のままで、根拠を流す記述が無い。ISSUE-33 が求めているのは
skip の妥当性を見る材料なので、この受け渡しが無いと足した欄がゲート側へ出てこない。

**2. 関連節の規定リストに置き場が無い。** e2e skill の「関連 CLAUDE.md ルール」節は、この skill が
噛み合うプロジェクト側の規定を 3 つ列挙している。Phase 1 の材料 2 と Phase 2 の置き場の材料 3 が
新たに読みに行く「UI / E2E の置き場の規定」がそこに入っていない。同じファイルの中で、手順が参照
する規定と節が列挙する規定がずれている形で、どの検査も見ない。

## タスク

- [ ] gate の出力フォーマットが skip の根拠を受ける形を決める。ISSUE-33 の追記と衝突しないこと
- [ ] e2e skill の関連節へ置き場の規定を足す。手順が読む材料と節の列挙を一致させる
- [ ] 足したあと、手順が読む材料の集合と節の列挙が一致していることを確かめる。片方だけ直すと
      同じずれが残る

## 関連

ISSUE-23 がこの 2 件を横断検証の「誰も扱わなかった面」として切り出した元
ISSUE-33 (gate の出力が全レーン skipped でも Merge OK を許す。1 つ目の受け渡し先)
ISSUE-47 (gate の Phase 1 の同時起動数。同じ skill の起動条件を扱い、ISSUE-23 で記述を訂正した)
