# fix: e2e skill が新たに読む置き場の規定が gate と関連節へ通っていない

## 背景

ISSUE-23 の B1 で `dev-workflow:e2e-scenario-impact-check` の判定条件からディレクトリ名を落とし、
UI と E2E の置き場を「呼び出し元から渡された値 → プロジェクトの CLAUDE.md の規定 → 内容で判定」の
順で決める形にした。この変更で 2 箇所が取り残されている。どちらも同じ変更に由来する。

**1. skip の根拠が呼び出し元へ届かない。** Phase 1 の skip 出力に「判定の根拠 (何を何件見たか)」を
足したが、`dev-workflow:pre-merge-quality-gate` の出力フォーマットは skip 理由を
`skipped (reason: ...)` の 1 行で受ける形のままで、根拠を流す記述が無い。ISSUE-33 が求めているのは
skip の妥当性を見る材料なので、この受け渡しが無いと足した欄がゲート側へ出てこない。

**2. 関連節の規定リストに置き場が無い。** e2e skill の「関連 CLAUDE.md ルール」節は、この skill が
噛み合うプロジェクト側の規定を 3 つ列挙している。Phase 1 の材料 2 と Phase 2 の置き場の材料 3 が
新たに読みに行く「UI / E2E の置き場の規定」がそこに入っていない。同じファイルの中で、手順が参照
する規定と節が列挙する規定がずれている形で、どの検査も見ない。

## 配布先での初回観測 (2026-09-17)

dotfiles が v0.8.0 へ pin を上げる PR で、マージ前ゲートからこの skill が 1 回呼ばれた。呼び出し元は
置き場を渡しておらず、dotfiles の CLAUDE.md にも置き場の規定が無いので、材料 3 で変更 6 件の中身を
読んで判定している。Phase 2 へは進まず (Skip OK)、agent は起動していない。pytest のファイルは
import を読んでブラウザ系のランナーではないと判定され、E2E と取り違えられなかった。Cannot assess も
出ていない。ディレクトリ名を持たない配布先で、B1 の変更が skip を能動的に判定した実例になる。

判定の根拠の行は skill の出力に出たが、ゲートの出力へ写す枠が無かった。観測した側は
`completed (Skip OK、判定の根拠: 材料 3 / 6 ファイル)` と書いた。skill 自身が能動的に判定した skip
だからという理由で、ゲートの書式が例に挙げる `skipped (reason: ...)` とは逆の側に置いている。
1 つ目の問題がそのまま現れた形で、ISSUE-33 がレーンごとに skip の可否を分けるときも、この形の skip を
どちらに数えるかが前提になる。

判定に迷った点が 2 つ報告された。どちらも材料 3 の例示が扱っていない。

- hook が Claude Code へ返す通知文は「画面に出る文字列」にあたるか。観測した側は、locator が当たる
  対象が無いので画面ではないと判定した。CLI やエージェント向けの文字列は例示に無い
- 補助の grep でブラウザ系ランナーの語が apm.yml と lockfile に当たった。skill のパッケージ名に
  含まれていただけで、中身を読んで除外している。名前の一致はテストコードの証拠にならない
